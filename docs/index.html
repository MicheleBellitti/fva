Le tre cose da capire della mappa

Il worker GPU è un servizio condiviso

Gira sull'host della macchina con la scheda, fuori da Docker, e consuma una coda in Postgres. Chiunque può mettere una partita in coda: chi lavora sull'assistente non ha bisogno della GPU sul proprio computer, gli basta il bucket condiviso per leggere i risultati.

Due sistemi, un contratto, nessuna chiamata diretta

Il worker non parla con l'API e l'API non parla con il worker. Comunicano solo attraverso Postgres e il bucket. È ciò che rende le due aree sviluppabili in autonomia — e testabili con dati sintetici.

L'API non ha GPU e non ne avrà

A runtime l'assistente fa una query SQL e due chiamate a un provider LLM. Tutto il lavoro pesante è già stato fatto dal worker. Per questo in produzione l'API scala a zero su un container serverless.

Scritto dal worker, letto dalla derivazione e dalle viste

~800k righe per partita. Non va in Postgres: Polars lazy su Parquet partizionato legge 60 MB in 200 ms, e non serve mai interrogare il tracking per riga singola.

Immutabile per versione

Una nuova pipeline_version scrive una nuova partizione. I vecchi risultati restano e si confrontano.

DSL di query assistente

L'LLM sceglie tra opzioni chiuse, non scrive. EventType e MetricName sono enum in core (ADR-013): il DSL ne ricava i Literal, e i registry dei detector e delle metriche si validano contro di loro.

EventType  = Literal[tuple(e.value for e in core.EventType)]   # ADR-013
MetricName = Literal[tuple(m.value for m in core.MetricName)]
Zone = Literal["defensive_third","middle_third","final_third",
               "left_flank","center","right_flank","box"]

class TimeWindow(BaseModel):
    half: Literal[1, 2] | None = None
    clock_from_min: int | None = Field(None, ge=0, le=130)
    clock_to_min:   int | None = Field(None, ge=0, le=130)
    last_n_min:     int | None = Field(None, ge=1, le=90)
    model_config = {"extra": "forbid"}

class FindMoments(BaseModel):
    intent: Literal["find_moments"]
    match_ids: list[str] = Field(min_length=1)
    event_types: list[EventType] = Field(min_length=1)
    team: Literal["A", "B", "both"] = "both"
    zone: Zone | None = None
    time: TimeWindow | None = None
    min_confidence: float = Field(0.5, ge=0, le=1)
    limit: int = Field(20, le=100)
    model_config = {"extra": "forbid"}

class ComputeMetric(BaseModel):
    intent: Literal["compute_metric"]; match_ids: list[str]
    metric: MetricName; team: Literal["A", "B"]
    time: TimeWindow | None = None
    group_by: Literal["match", "half", "window"] = "match"

class CompareMatches(BaseModel):
    intent: Literal["compare"]; match_ids: list[str] = Field(min_length=2)
    metric: MetricName; team: Literal["A", "B"]

class SimilarMoments(BaseModel):
    intent: Literal["similar"]; anchor_event_id: str
    match_ids: list[str] | None = None; limit: int = 10

Query = Annotated[Union[FindMoments, ComputeMetric, CompareMatches,
                        SimilarMoments], Field(discriminator="intent")]
def compile_find_moments(q: FindMoments) -> tuple[str, dict]:
    sql = """SELECT e.id, e.match_id, e.type, e.team, e.t_video, e.half,
                    e.match_clock, e.x_pitch, e.y_pitch, e.confidence
             FROM events e JOIN matches m ON m.id = e.match_id
                  AND e.pipeline_version = m.active_pipeline_version
             WHERE e.match_id = ANY(:match_ids) AND e.type = ANY(:types)
               AND e.confidence >= :minc AND e.status <> 'retracted'"""
    params = {"match_ids": q.match_ids, "types": q.event_types,
              "minc": q.min_confidence}
    if q.team != "both":
        sql += " AND e.team = :team"; params["team"] = int(Team[q.team])
    if q.zone:
        sql += f" AND {ZONE_PREDICATES[q.zone]}"   # predicati fissi
    if q.time:
        sql, params = apply_time_window(sql, params, q.time)
    sql += " ORDER BY e.t_video LIMIT :limit"; params["limit"] = q.limit
    return sql, params

03

Milestone

Venti settimane a dieci ore la settimana per area. Le settimane per milestone sono modificabili; il budget si ricalcola e si confronta con la somma delle ore dei task nella board.

Il punto di contatto è P2.7 → S2.1, all'inizio di M2: la prima timeline reale passa dal worker al bucket condiviso, e l'assistente passa dai dati sintetici a quelli veri. Il generatore sintetico deve aver prodotto dati sporchi, altrimenti qui si rompe tutto insieme. Una settimana di assestamento è normale.

python 3.12 · uv · node 20 · pnpm · docker

make dev

Nessuna GPU. Fino a M2 dati sintetici; poi Parquet ed eventi dal bucket condiviso. Prima la parte deterministica (DSL, compilatore, test), poi l'LLM.

Convenzioni

Git e PR

  • Branch: perc/<topic>, asst/<topic>, core/<topic>
  • PR piccole, sotto le 400 righe. Template: cosa / perché / come testato
  • Conventional commits
  • core/ e docs/schema.md → due reviewer. Il resto uno, entro 48 h
  • Squash merge; main sempre verde

Codice

  • ruff + pyright strict in CI, bloccanti
  • Chiavi stringa come costanti: S.RESULTS, Cls.BALL
  • tests/test_graphs.py costruisce ogni combinazione di config del DAG e il grafo Burr
  • Ogni file di config validato contro lo schema Pydantic
  • Nessun secret nel repo; .env.example aggiornato
  • AGENTS.md alla radice

Dati

  • confidence, coverage, pipeline_version: obbligatori
  • Nuova versione = nuova partizione Parquet, mai sovrascrittura
  • I pesi sul bucket, nome = sha
  • track_id non è un giocatore

Definition of done di un task

  • Test in CI
  • Tocca DAG o grafo → test_graphs verde
  • Tocca lo schema → migrazione + docs/schema.md
  • È una decisione → ADR
  • Una riga in STATUS.md
